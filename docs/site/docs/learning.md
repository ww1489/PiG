# PiG 源码学习篇

这是一套面向 Go 开发者的中文 PiG 学习文档。篇章、小节主题和阅读顺序对应 [Pi Agent Book 的源码学习篇](https://dg-ai-notes.pages.dev/)，即截图中的 M01—M10；不包含该网站另外的实战篇。正文根据当前 PiG 的 Go 实现重新整理，不把 TypeScript 示例改名后当作 PiG API。

PiG 是 [Pi](https://github.com/earendil-works/pi) 的 Go 实现，Pi 是行为参考实现。PiG 由 Michael Kinsy 创建，最初开发于 Hewlett Packard Enterprise。PiG 不是 Pi 官方项目，也不代表 Pi 维护者的认可。上游使用文档见 [Pi documentation](https://pi.dev/docs/latest)。

## 2. 阅读方式

先读第1—2章建立目录和类型地图，再按第3—7章跟踪一次运行，最后读第8—10章理解长会话。每章保留参考教程的二级至四级主题及先后关系；标题中的旧版本断言按当前实现修正，编号统一为阿拉伯数字，方便文档站点生成锚点。

建议同时打开源码和测试。每章既有解释性流程图，也有具体类型、调用片段和完整程序；章末“源码阅读与练习”给出实际文件和应检查的断言。示例分成三类：

| 示例形式 | 如何使用 | 验证边界 |
|---|---|---|
| 以 `package` 开始的完整 Go 文件 | 在仓库内独立目录保存；main 可运行，其他包是辅助函数或扩展工厂 | 文档检查对完整文件编译；扩展工厂需由宿主加载 |
| 函数内部片段或类型摘录 | 放进前文说明的调用环境，补齐已说明的变量与导入 | 检查语法不等于独立编译；不是另一套完整实现 |
| text/JSON 流程与记录示意 | 对照源码理解边界与数据变化 | 省略字段的消息不是完整请求或可导入 fixture |

无需模型凭据的实验包括：第3章双轮工具循环、第4章注册假 Provider、第5章参数验证、第6章消息转换、第8章截断与 UTF-8 边界、第9章压缩阈值、第10章内存会话分支。它们调用真实 PiG 函数，假模型回复和教学数据会明确标注。第1章 Session 程序及第4章 Ollama 请求则需要已配置的模型服务，不能把编译通过当作已成功联网。更多完整嵌入示例见 [SDK 文档](zh-sdk.md) 和仓库 `examples/sdk/main.go`。

术语约定：

- **Provider**：负责认证、协议转换和模型通信的提供方实现；提供商品牌与 API 协议类型是两个字段。
- **Transcript**：按顺序保存、规范化后交给 Provider 的消息记录，包括系统状态及工具声明的变化。
- **Turn**：一次 assistant 响应及其工具批次；本教程用 Trace 表示一次完整运行，Trace 不是必须存在的同名 Go 类型。
- **Session**：拥有模型运行状态、消息历史和产品级行为的会话。磁盘中的 Entry 是记录节点，不等同于一条模型消息。
- **钩子**：宿主在特定边界调用的扩展回调。是否能修改结果、阻止操作或要求继续，取决于该钩子的契约。

## 4. 与参考教程的重要对应关系

| 原教程的位置 | 当前 PiG 应怎样理解 |
|---|---|
| 第2章实验性 orchestrator | 保留“核心之外的编排”位置，介绍当前附加包与实验目录，不虚构同名公开包。 |
| 第3章“stopReason 是唯一信号” | 工具调用内容、错误状态、队列、`FinishTurn` 和准备钩子共同决定控制流。 |
| 第4章“五级 ThinkingLevel” | 当前包含 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`，以模型能力为准。 |
| 第5章“永不抛出” | 普通工具失败变成结果消息；基础设施、事件接收器等错误仍可能向调用者返回。 |
| 第6章“三种模型消息”与声明合并 | 当前有 `system`；Go 使用封闭接口、带标签结构与显式转换，不使用 TypeScript 声明合并。 |
| 第7章“10 种事件”“subscribe 不等” | 事件种类已经扩展；`coding.Session.Subscribe` 同步调用回调，观察权限不等于异步执行。 |
| 第8章“无限对话” | 历史可以持续保存，但模型只看到有限投影，摘要有损，不承诺无限精确记忆。 |
| 第9章“只在 agent_end 后压缩” | 同一次运行的后续 assistant 请求之前也有预防性压缩。 |
| 第10章“9 种 Entry”“等 assistant 才落盘” | 增加 `usage`、`context_edit`；当前 user 或 assistant 都能触发首次落盘。 |

PiG 有意保留的可观察差异使用 `D<N>` 编号。遇到编号时，可查 [差异记录](https://github.com/MichaelKinsy/PiG/blob/c64bebd820e20411599a8b1e8e52aa92b4a2ed82/docs/parity/DIVERGENCES.md) 与 [附加能力记录](https://github.com/MichaelKinsy/PiG/blob/c64bebd820e20411599a8b1e8e52aa92b4a2ed82/docs/additive-features.md)。版本变化、Go 的语言表示差异和已编号行为差异是三件不同的事。

## 5. 安全与验证边界

阅读源码不需要模型密钥。实际运行 `pig`、扩展或带外部程序的测试前，使用临时项目和独立配置目录，同时隔离 `HOME`、`PIG_HOME`、`PI_HOME`、`PIG_CODING_AGENT_DIR`、`PI_CODING_AGENT_DIR`，避免触及真实认证文件。Go 工具链版本以仓库 `.go-version` 为准，当前为 Go 1.27.3。

工具和扩展可以操作文件、启动进程及访问网络。子进程隔离不等于安全沙箱；执行不可信项目应另行使用受控容器或虚拟机。详见 [安全说明](zh-security.md)。

本文描述源码基线，不承诺所有 Provider、平台和扩展组合都已由本次文档整理实测。文档清单、链接与结构检查也不等同于运行行为对齐证明。
